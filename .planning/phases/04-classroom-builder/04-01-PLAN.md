**Table 1: classroom_sections (per D-15)**
```sql
CREATE TABLE classroom_sections (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  classroom_id  UUID NOT NULL REFERENCES classrooms(id) ON DELETE CASCADE,
  name          TEXT NOT NULL,
  sort_order    INTEGER NOT NULL DEFAULT 1000,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

RLS policies on classroom_sections (4 policies: SELECT, INSERT, UPDATE, DELETE). All use the subquery chain pattern `(SELECT auth.uid())`:
- SELECT: `classroom_id IN (SELECT id FROM classrooms WHERE tutor_id IN (SELECT id FROM tutors WHERE user_id = (SELECT auth.uid())))`
- INSERT: same check in WITH CHECK
- UPDATE: same check in USING
- DELETE: same check in USING

**Table 2: classroom_cards (per D-16)**
```sql
CREATE TABLE classroom_cards (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  section_id    UUID NOT NULL REFERENCES classroom_sections(id) ON DELETE CASCADE,
  card_type     TEXT NOT NULL CHECK (card_type IN ('text', 'pdf', 'image', 'link')),
  content       TEXT,
  title         TEXT,
  storage_path  TEXT,
  sort_order    INTEGER NOT NULL DEFAULT 1000,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Note: sort_order is append-only for cards in v1.0 — card reorder is deferred per CONTEXT.md Deferred Ideas.

RLS policies on classroom_cards (4 policies: SELECT, INSERT, UPDATE, DELETE). Use deeper subquery chain per Research Pitfall 5:
- `section_id IN (SELECT id FROM classroom_sections WHERE classroom_id IN (SELECT id FROM classrooms WHERE tutor_id IN (SELECT id FROM tutors WHERE user_id = (SELECT auth.uid()))))`

Enable RLS on both tables with `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`.

Do NOT use a custom enum type for card_type — use TEXT with CHECK constraint. This avoids migration complexity and works the same way.
